## 2026-07-28 20:14 UTC - Magi-02 Android Table Scroll Root Cause

- Final working solution for repeated Android horizontal table-scroll issue in `/nerv/central-dogma/magi-02`: the table conversion alone was not enough. The real blocker was parent CSS grid/card layout. Some wrappers around Class A/B/C panels did not have `min-width: 0`, so CSS grid let the card expand to the table's min-content width. Then `.module-shell { overflow: hidden }` clipped the right side, making Android feel like the table could not scroll to the last columns.
- Working fix deployed in commit `de2c808059b9b83a34d687a059c61df7803f570e`: add `min-width: 0` to `asset-class-grid`, `asset-class-card`, `class-a-controls`, `class-b-controls`, `class-c-controls`, and their direct child wrappers; add `contain: inline-size` to `.data-table-scroll` so wide table content no longer contributes to parent grid sizing.
- Lesson for future Magi-02 frontend work: for horizontally scrollable tables inside CSS grid/card layouts, always fix both layers:
  - Child layer: real table inside a dedicated scroll viewport with a fixed/min table track.
  - Parent layer: every grid/card wrapper up the chain needs `min-width: 0`, and the scroll viewport should use inline-size containment if table width must not escape upward.
  Verifying only live source/build is insufficient; Android scroll bugs need actual layout/gesture testing when a browser environment is available.

## 2026-07-28 20:29 UTC - Magi Charting And Approval Preferences

- User likes TradingView Lightweight Charts for Magi charting, but reports a recurring bug: on first load the chart appears for a split second and then becomes empty. Read-only inspection suggested this pattern exists in multiple Magi apps such as `magi-15`, `magi-17`, `magi-18`, `magi-mtfa`, and `magi-16`, not Magi-02 specifically.
- Likely Lightweight Charts root cause to remember: React components create charts with `createChart(..., { autoSize: true })` and a `ResizeObserver` later calls `chart.resize(chartHost.clientWidth, chartHost.clientHeight)` while the container is temporarily `0x0` or otherwise unstable. The chart is then resized to an empty canvas after briefly rendering.
- Durable charting guardrails requested by user for Noah/engineering skill:
  - Chart wrapper must have stable dimensions/min-height before init.
  - Only initialize Lightweight Charts after measured width and height are both > 0.
  - ResizeObserver must ignore `0x0` sizes.
  - Resize should be debounced through `requestAnimationFrame`.
  - Avoid destroy/recreate on every data/theme change; update series data separately with `setData` where possible.
